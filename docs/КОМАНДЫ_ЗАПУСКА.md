# Команды запуска NoteTag и тестов

Этот файл предназначен для запуска проекта и демонстрации тестов на локальном компьютере. Backend написан на TypeScript и NestJS, frontend — на React и JavaScript, база данных — PostgreSQL, тестовый раннер — Vitest.

## Быстрый запуск завтра на подготовленном компьютере

Локальная папка уже содержит установленные зависимости и файлы `.env`. PostgreSQL-база `notetag_acceptance` создана, миграция применена, демонстрационные данные добавлены.

Открой первый терминал:

```bash
cd /Users/zhora_ishunin/Desktop/NoteTag/ZenonRa-NoteTag
npm run migration:run
npm run seed
npm run start:dev
```

Что делает каждая команда:

- `migration:run` применяет ещё не выполненные TypeORM-миграции. Повторный запуск безопасен;
- `seed` добавляет демонстрационные аккаунты, заметки и теги. Повторный запуск не создаёт дубликаты;
- `start:dev` запускает backend в режиме разработки на `http://localhost:3000`.

Открой второй терминал:

```bash
cd /Users/zhora_ishunin/Desktop/NoteTag/ZenonRa-NoteTag
npm run frontend:start
```

Frontend откроется на `http://localhost:5173`.

Swagger backend доступен на `http://localhost:3000/api/docs`.

Демонстрационные аккаунты:

| Роль | Логин | Пароль |
| --- | --- | --- |
| Клиент | `demo_andrey` | `password123` |
| Администратор | `demo_admin` | `admin123` |

Для остановки frontend или backend нажми `Ctrl+C` в соответствующем терминале.

## Установка после нового клонирования

В корне проекта:

```bash
npm ci
npm run frontend:install
```

- `npm ci` устанавливает точные версии зависимостей backend из `package-lock.json`;
- `frontend:install` устанавливает точные версии зависимостей из `frontend/package-lock.json`.

Создай локальные файлы окружения, если их нет:

```bash
cp .env.example .env
cp frontend/.env.example frontend/.env
```

В корневом `.env` необходимо указать доступ к PostgreSQL и заменить `JWT_SECRET`. Файлы `.env` исключены из Git и не отправляются в репозиторий.

Пример локальной конфигурации:

```env
PORT=3000
DB_HOST=localhost
DB_PORT=5432
DB_USERNAME=postgres
DB_PASSWORD=postgres
DB_DATABASE=notetag
JWT_SECRET=replace_with_a_long_random_secret
JWT_EXPIRES_IN=1d
```

После создания базы выполни:

```bash
npm run migration:run
npm run seed
```

## Запуск backend

### Режим разработки

```bash
npm run start:dev
```

NestJS следит за TypeScript-файлами и перезапускает backend после изменения кода.

### Production-режим

```bash
npm run build
npm run migration:run:prod
npm run start:prod
```

- `build` компилирует TypeScript в папку `dist`;
- `migration:run:prod` применяет скомпилированные миграции;
- `start:prod` запускает `dist/main.js`.

## Запуск frontend

Из корня проекта:

```bash
npm run frontend:start
```

Команда запускает Vite development server. Frontend берёт адрес API из `frontend/.env`:

```env
VITE_API_URL=http://localhost:3000
VITE_DEMO_MODE=false
```

Проверка production-сборки frontend:

```bash
npm run frontend:lint
npm run frontend:build
```

## Запуск через Docker Compose

Если Docker Desktop запущен, весь проект можно поднять одной командой:

```bash
docker compose up --build
```

После запуска контейнеров добавь демонстрационные данные:

```bash
docker compose exec backend npm run seed:prod
```

Адреса остаются теми же:

- frontend — `http://localhost:5173`;
- backend — `http://localhost:3000`;
- Swagger — `http://localhost:3000/api/docs`;
- PostgreSQL — `localhost:5432`.

Остановка контейнеров без удаления данных:

```bash
docker compose down
```

## Команды тестов

### Быстрые unit-тесты

```bash
npm test
```

Запускает 68 тестов backend и чистых frontend-функций. Реальная база и локальный HTTP-порт не требуются.

Как реализовано:

- TypeORM-репозитории и сервисы заменяются моками `vi.fn`;
- `mockResolvedValue` имитирует успешные асинхронные ответы;
- `mockRejectedValue` имитирует ошибки;
- проверяются результаты, исключения и аргументы вызовов;
- backend-тесты написаны на TypeScript в `*.spec.ts`;
- frontend helper-тест находится в `frontend/src/api/notetag.test.js`.

### Unit-тесты в watch-режиме

```bash
npm run test:watch
```

Vitest остаётся запущенным и автоматически повторяет связанные тесты после изменения файлов. Используется при разработке.

### Unit-тесты с покрытием

```bash
npm run test:cov
```

Запускает unit-тесты и формирует отчёты в `coverage/`.

Минимальные пороги в `vitest.config.mts`:

- statements — 95%;
- branches — 80%;
- functions — 95%;
- lines — 95%.

Последний проверенный результат:

- statements — 99,37%;
- branches — 84,61%;
- functions — 100%;
- lines — 100%.

### HTTP e2e-тесты

```bash
npm run test:e2e
```

Запускает три теста из `test/auth.e2e-spec.ts` через отдельную конфигурацию `vitest.e2e.config.mts`.

Как реализовано:

- Nest TestingModule создаёт тестовое приложение;
- Supertest отправляет настоящие HTTP-запросы;
- глобальный ValidationPipe работает как в основном приложении;
- `AuthService` заменён мок-объектом, поэтому проверяется HTTP-слой без реальной БД;
- проверяются статусы 201, 400 и 200 для регистрации и входа.

Тест открывает случайный локальный порт только на время выполнения.

### Интеграционные тесты PostgreSQL

```bash
npm run test:db
```

Запускает пять тестов из `test/database.integration-spec.ts` через `vitest.db.config.mts`.

Как реализовано:

- драйвер `pg` подключается к реальной тестовой базе;
- перед каждым сценарием выполняется `BEGIN`;
- после каждого сценария выполняется `ROLLBACK`;
- тестовые строки не остаются в базе;
- проверяются SQLSTATE и имя PostgreSQL constraint.

Проверяемые ограничения:

1. уникальность `users.login`;
2. каскадное удаление notes, tags и note_tags;
3. обязательный `notes.content`;
4. внешний ключ `notes.user_id`;
5. значение `users.role = 'client'` по умолчанию.

Сначала тест читает переменные `TEST_DB_*`. Если они не заданы, используются
обычные параметры `DB_*` из корневого `.env`. Последние резервные значения:

```text
host: localhost
port: 5432
user: postgres
database: notetag_acceptance
```

Для другой среды задай переменные перед командой:

```bash
TEST_DB_HOST=localhost \
TEST_DB_PORT=5432 \
TEST_DB_USERNAME=postgres \
TEST_DB_PASSWORD=postgres \
TEST_DB_DATABASE=notetag \
npm run test:db
```

Перед первым запуском DB-тестов к выбранной базе должна быть применена миграция.

### Полная проверка проекта

```bash
npm run test:all
```

Команда последовательно выполняет:

1. ESLint backend;
2. TypeScript production-сборку backend;
3. unit-тесты с покрытием;
4. HTTP e2e-тесты;
5. PostgreSQL integration-тесты;
6. lint frontend;
7. production-сборку frontend.

Перед `test:all` PostgreSQL должен быть запущен, база `notetag_acceptance` должна существовать, а миграция должна быть применена.

## Если порт уже занят

Проверить процессы на основных портах:

```bash
lsof -nP -iTCP:3000 -sTCP:LISTEN
lsof -nP -iTCP:5173 -sTCP:LISTEN
lsof -nP -iTCP:5432 -sTCP:LISTEN
```

- 3000 — backend;
- 5173 — frontend;
- 5432 — PostgreSQL.

Если NoteTag уже запущен, второй экземпляр запускать не нужно.
